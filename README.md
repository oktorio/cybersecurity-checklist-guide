# Cybersecurity Checklist for Auditee (v3)

**Regulatory baseline reviewed as of 15 August 2026.**

Version 3 turns the original questionnaire into an **audit / supervisory working-paper toolkit** for commercial-bank cybersecurity and technology-risk reviews.

## What changed in v3

- **125 audit controls** structured using **NIST CSF 2.0** functions: Govern, Identify, Protect, Detect, Respond, and Recover.
- Added **Expected Evidence**, **Audit / Test Procedure**, **Applicability**, **Default Risk**, **Result**, **Auditor Notes**, and **Finding Reference** fields.
- Added **PADK OJK No. 1 Tahun 2026** as the current detailed IT-governance / IT-risk baseline for commercial banks.
- Retained and corrected **SEOJK 29/SEOJK.03/2022** cyber-resilience requirements, including OJK cyber-incident timelines.
- Added **SEOJK 24/SEOJK.03/2023** digital-maturity coverage.
- Added governance, digital-service, consumer-protection, privacy and conditional payment-system overlays.
- Migrated international mapping to **NIST CSF 2.0**, **CIS Controls v8.1**, and current API guidance.
- Moved **SEOJK 21/SEOJK.03/2017** and **FFIEC CAT** to legacy status.

## Files

- `checklist/Cybersecurity_Checklist_Auditee_v3.xlsx` — primary audit working paper with dashboard and data-entry fields.

- `docs/REFERENCES.md` — current regulatory and framework reference map.

- Existing v2 files are retained for historical comparison.

## Intended use

1. Define the auditee and applicable regulatory perimeter.
2. Filter controls by **Applicability**, NIST function, domain and default risk.
3. Request the listed **Expected Evidence**.
4. Perform the **Audit / Test Procedure**, including sampling and reperformance where relevant.
5. Record the result as `Comply`, `Partially Comply`, `Non-Comply`, `N/A`, or `Not Tested`.
6. Link exceptions to a formal finding or supervisory follow-up.

## Important applicability note

This repository is an audit/supervisory aid, not a substitute for the official regulation text or entity-specific legal interpretation. Conditional Bank Indonesia / payment-system controls must be applied based on the auditee's actual licensing, activities, infrastructure participation and regulatory classification.
